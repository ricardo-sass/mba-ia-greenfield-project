## Real-flow technical acceptance — 2026-09-28

**Verdict:** passed. The HTTP-to-storage-to-worker coverage gap is closed by `nestjs-project/test/videos-flow.e2e-spec.ts`, included in the default `npm run test:e2e` command.

The suite boots the real `AppModule` and `VideosWorkerModule` in separate Nest application contexts inside the test process. PostgreSQL, Redis/BullMQ and MinIO are real Compose services; FFmpeg/ffprobe execute normally. Storage, queue publisher, processor, repositories, JWT authentication and Nano ID are not mocked. Only queue configuration is overridden: a unique Redis prefix isolates the suite from other workers, and two attempts with a 1-second initial backoff exercise real retry exhaustion quickly. The suite creates confirmed account fixtures and authenticates through `POST /auth/login`.

### Audit follow-up: findings 1 and 2 (2026-09-24)

- Finding 1: Claude/Codex instructions, phase context/plan, decision clarifications and multipart test specs now match the initial `draft` status and real open-upload checks.
- Finding 2: storage requests use the internal S3 client; signatures use a separate client configured by `STORAGE_PUBLIC_ENDPOINT`. Both local defaults use the Compose service name `minio`, with no `localhost` storage endpoint. The external client must resolve that name through DNS/hosts or supply a reachable public storage domain.

Multipart PUT, range GET (206) and attachment GET (200) passed from the host using `curl --resolve` to the Docker host's LAN address while preserving signed host `minio`.
